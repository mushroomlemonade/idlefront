# IdleFront v26.4

## Scope

- Versioned native nation strategy for newly created quickplay, longplay and idlefront worlds: coordinated land/naval objectives, opportunistic targeting, expansion reinforcement, economic development, and nuclear follow-through.
- Fleet replenishment is an additional nation control. Existing native warship spawning, retaliation, combat and escorts remain available. Normal resource costs, construction checks, alliances and grace rules still apply.
- Small pressure attacks do not automatically cause full diplomatic hostility; substantial pushes still do.
- Compact focus/idle command-bar actions, reduced navbar padding and curved outer structure buttons, using the existing UI and camera systems.
- Landing screen displays v26.4 (v26.4 dev in development).

## Compatibility and scope exclusions

Existing saved worlds retain their recorded strategy version. New persistent pressure worlds use `nationStrategy: "v2"`; v1 remains available for existing replay/recovery. Fog games retain the existing planner to avoid new hidden-state access. Humans and tribes do not use the nation planner.

`fleetAutomation: "v26.3"` is a simulation protocol marker, not the displayed application release, and intentionally remains unchanged. Identity synchronization, combat and population formulas are preserved. No database migration is required.

Unfinished learned-AI experiments, their datasets and temporary artifacts are not part of this release. The production regression fixture is self-contained in `tests/util/NavalScenario.ts`.

## Release gates

- Release suite: **3,648 passed, zero failed or skipped**. The suite covers all release tests; unrelated untracked learned-AI research tests are outside this release. The bundled Git shell was added to PATH for Windows shell-script tests.
- Root TypeScript and Expo/mobile TypeScript passed.
- ESLint and oxlint passed for application/tests and the replay-review utility; commit hooks also check all staged code.
- Vite production build passed. Existing warnings remain for runtime-resolved stone textures, mixed static/dynamic imports and large bundles.
- The initial broad working-tree test discovery also encountered three untracked research files using Node's test runner and a missing `sh` PATH entry; the final release run corrected the environment and scope, without weakening or skipping any release test.

## Deployment boundary

The repository has since moved to independent history. Complete
[repository migration](repository-migration.md) before pointing a production
updater here; do not pull this history into the old live checkout. Source
publication is verified, but production cutover remains the operator's task.

Publish to `mushroomlemonade/idlefront` main only. The repository's deployment notice is not an executable production deployment workflow. Do not run inherited upstream OpenFront release/deployment workflows. Production completion requires checking the live `gitCommit` at `https://www.idlefront.io/api/client-config`, not merely a successful Git push.

Preview was backed up and restarted with approval. Browser/device visual verification remains unperformed because Windows denied interactive desktop access. Automated UI tests and the earlier user playtest do not replace a fresh iPhone layout check. Small native fixtures are not proof of competitive strength or 27x-map performance.
