# UHD Earth 27× — experimental development checkpoint

## Scope and availability

27× means area relative to the original 4,108 × 1,948 Earth, not 27× each dimension. Versioned map `ExpandedGiantWorldUHD27v1` is 21,344 × 10,124 (216,086,656 tiles), packaged in 210 terrain pages. It is a public custom-game option, not an automatic scheduled-game replacement. Scheduled games stay on 4× Earth with standard modifiers. This custom preset uses 5× ship/train trade and 15× attack slowdown, matching HD 9×. Great Lakes uses 10× ship/train trade.

Active games were cancelled after a verified SQLite backup at `.data/backups/worlds-before-custom-and-27x-20260908.sqlite`. Journals/history were not deleted. The user now allows UI updates during playtests unless they say otherwise. No production push was made.

## Terrain and navigation

Built from the same 21,600 × 10,800 source and Natural Earth waterways as HD 9×, not by enlarging the 9× bitmap. Provenance and asset attribution accompany the generated map. This is approaching the master raster's native resolution; further enlargement alone will not create real geographical detail.

Generation: `generate-hd-earth.py --area27 --output-root=FRESH_DIRECTORY`, which invokes isolated `generate-expanded-earth.mjs --variant=uhd27 --terrain-bin=... --output-root=...`. Final validated candidate: `.data/earth-uhd27-v1/final`. The earlier incomplete export under `.data/earth-uhd27-v1/maps` is not installed. Exporter fractional-radius spawn snapping was corrected. Standard generator image/info are installed alongside runtime pages.

18 geographic connectivity checks pass across full/half resolution. Seven production-engine routes pass with zero dry points, adjacent steps, water-safe diagonal corners, correct endpoints and no long ocean detour: Panama, Suez, Bosphorus, Dardanelles, Mississippi, Rhine, Amazon. Measured per-route query cost was 0.27–8.86 ms in this sample, not a fleet-load guarantee.

The old half-resolution path expansion could place boats on dry banks. Water-only route chains now validate against full-resolution terrain and repair invalid paths using bounded cardinal A* in a corridor. Valid routes and rail chains remain unchanged. Repair has a 200,000-node ceiling and safely returns no route if exhausted; it does not guarantee every possible route or global shortest paths. Existing regression tests formerly asserting land crossings now require rejection. 32 focused water/custom-game tests passed, and TypeScript no-emit checking passed.

**Trent–Severn is NOT navigable in this candidate.** A bounded Trenton-to-Port Severn connectivity test fails; broad Great Lakes connectivity is not a substitute. Ontario hydrography was investigated but not incorporated because the sampled named lines did not provide a complete trustworthy route. Do not draw an invented straight canal or advertise it as working. Native Panama crop was visually inspected; mobile/client rendering has not been benchmarked in this pass.

## Preliminary simulation measurements

Same headless seed/configuration, 2,000 bots, 900 ticks, first 302 excluded. Snapshot recording included. Scripts and raw reports are retained in `.data/earth-uhd27-v1`.

| Metric | HD 9× | UHD 27× |
| --- | ---: | ---: |
| Mean simulation tick | 32.96 ms | 34.08 ms |
| p95 simulation tick | 42.83 ms | 44.42 ms |
| Maximum tick | 147.50 ms | 154.13 ms |
| Ticks over 100 ms | 11 / 598 | 13 / 598 |
| Map/game load | 1.34 s | 3.95 s |
| Sampled peak process RSS | 950 MB | 1,473 MB |
| Snapshot encoding | 92.88 ms | 108.87 ms |
| Snapshot bytes | 3,049,176 | 3,064,304 |

This is startup/expansion only: all structure and vessel counts were zero at the end. It does NOT establish mature-economy capacity, sustained weeks-long throughput, concurrent-world capacity, network download performance or phone FPS. Do not convert these means into promised TPS. The backend already uses paged terrain and the client already has a paged renderer.

## Next scaling work

1. Reproducible mature-world fixture with ports, trains and active combat; profile pathfinding, target discovery, simulation and snapshot costs independently. Compare 9×/27× with identical activity counts and also activity proportional to map area.
2. Based on that profile, prioritize spatial/region indexes and incremental invalidation over repeated global candidate scans. Bound routing scratch and cache topology-derived work without changing legal trade targets or combat rules.
3. Profile browser visible-page uploads and entity drawing separately from server TPS. Preserve viewport-bounded page residency; batch/cull distant visual entities where measured. Avoid moving authoritative simulation back onto phones.
4. Measure memory with mature ownership and multiple worlds. Startup RSS alone is not a server provisioning number. Plan region ownership/worker decomposition only after identifying global dependencies and deterministic handoff costs.

Boat correctness remains a gate: if playtesting finds another bank crossing or refused necessary passage, treat it as a blocker rather than hiding it with a visual overlay.
