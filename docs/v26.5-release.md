# IdleFront v26.5

## Release scope

- Longplay performance: incremental pressure contacts, typed unit indexes,
  bounded catch-up delivery, compressed view state, shared rail/water corridors,
  warship routing/retry improvements, construction and port-selection caches.
- Server-owned shipping/rail corridor summaries and leaderboard history, available
  after a late join or reconnect without keeping a device connected.
- Leaderboard charts, metric sorting and time windows; mobile map panning work.
- Wider ownership IDs for large rosters. Preview longplay default is 3,000 tribes;
  the 16,000-bot experiment is not a performance recommendation.
- Versioned map-area trade density and economy-aware nation fleet targets for new
  longplay/idlefront worlds. Existing replay configuration remains supported.
- Archive-only identity fallback without changing authentication identities.
- Landing page displays v26.5 (v26.5 dev for development builds).

See [server history](server-world-history.md), [Newt profile](newt-late-game-profile.md),
[corridor brief](trade-corridor-performance-brief.md) and other profiling notes for
limits and measurements. No claim of steady overnight 10 TPS or completed iPhone
visual validation is made. Existing simulation markers such as `v26.3` are not
application release labels and remain unchanged.

## Deployment

Publish the accumulated source state to the canonical repository's main branch.
Production already reported its preceding main commit `d009f8a` on September 28;
older migration notes claiming it was disconnected are historical. Verify the
new live `gitCommit` before calling this release deployed. Do not restart the
separate preview backend or interrupt its active longplay for this release.

Local databases, credentials, diagnostic captures and generated build output are
excluded from source publication. Existing licensing and attribution are retained.
