# v26.3 implementation and release checklist

## Release candidate — September 22, 2026

The owner approved marking v26.3 and pushing to production after verification.
This section supersedes the historical preview notes below.

- Landing menu displays v26.3.
- Fleet size and ports/escort/patrol controls share a compact defense section;
  ongoing fronts and alerts have their own section, without a redundant outer box.
- Fleet orders are enabled by the control, default to zero ships, automatically
  use owned ports, preserve an absolute target, and retain native purchase rules.
- Shared slider and fleet styles are loaded once rather than injected per instance.
- Fleet dragging is contained within its control, with integer release snapping,
  matching fill/handle geometry, collision-avoiding labels and reduced-motion support.
- Idle mode uses the existing renderer, smaller camera-aware labels, visible
  subjects, and native manual/AFK pacing. Cinematic styling restores on resume.
- Release verification includes the full suite, type checking, lint and build.
  Final results are recorded in `docs/v26.3-release.md`.
- Production pulls/builds main independently. A pushed commit is not proof of
  live deployment. Real-device and large-world performance are not certified by
  automated UI tests; the user's iPhone playtests cover the iterations above.

## Implemented first pass

- Fleet settings are ordinary stamped intents, resolved by authenticated client
  identity. No target-player ID in the payload. Target 0–20 ships, reserve up to
  1 trillion gold, at most 64 explicitly selected owned ports.
- One purchase queued per decision. Revalidate reserve, ownership, port
  readiness, disabled units and fleet target at the native warship purchase.
  Native warships currently launch immediately; no artificial build delay was
  added. Pending purchases and any native under-construction ships count.
- Automation-built ships defend home waters or escort own trade/transports.
  Existing manually built ships remain untouched. Manual moves exclude a ship
  until settings are explicitly reapplied. Normal combat and repair remain native.
- Five-second-plus-player-stagger decisions, at most eight port candidates and
  four changed patrol orders per pass. Port chooser pages 32 rows; control
  readouts refresh once per simulation second instead of rebuilding each tick.
- Idle locks only the requesting device. It sets the existing mobilisation AFK
  condition, with no immunity/resources. Any manual command from another device
  ends explicit AFK without unlocking the idle device's UI. Resume restores the
  original camera. Game exit also cleans up the modal, timers and listeners.
- Basic camera tracks visible **own** trains, warships, cities and ports through
  the native camera/renderer. Reduced motion and manual motion-off are supported.
- Gold and sampled net gold/sec (including spending), fleet/combat count,
  attack/defense, visible-land rank and three bounded territory trend histories.
  Rank deliberately says "visible land rank"; hidden-player data is not invented.
- Radial menu prices reuse native buildable costs and refresh with the menu;
  insufficient gold is marked with text, not just colour. Relevant scroll
  surfaces use native scrolling and contain scroll chaining.

## Compatibility and activation

New persistent pressure worlds advertise `fleetAutomation: "v26.3"`. The client
does not expose the new commands to old running worlds. Requires an approved
backend restart and a **new** playtest world. No processes were restarted and
nothing was committed, pushed or deployed in this task.

Settings replay from the existing turn journal; no database migration. Old
recordings with no new intents have no fleet state and retain prior fleet/idle
hash contributions (zero). Previously pending nation-AI changes are preserved;
their historical replay compatibility is separate from these new opt-in orders.

## Cinematic preview follow-up

### Continuous tracking / missile shots

Latest director revision supersedes the earlier category rotation and single
warhead follow: priority is MIRV/group, hydro, atom, warship combat, moving train,
trade delivery, then other moving units. Cities/ports are not shot candidates.
Locality/fog gates remain: distant events do not trigger cross-map sweeps.
Existing train motion-plan length breaks train ties, without a route search.
Visible nearby enemy activity is eligible through the native spatial index.

MIRV separation now retains a bounded visible group and gradually fits its
spread/impact positions, followed by aftermath. Missile index inspection cap is 512. Hydro/atom pullback starts at an estimated three movement ticks from a
visible destination (not a guaranteed exact impact frame); native blast radius
sets framing. Edge concealment can limit how much destruction fits at once.
Native delivery popups remain; a 32-entry permitted own-player bonus buffer
supports brief delivery holds and exact gold-received readouts. No inferred
income is presented as a delivery. Same-owner/proximity MIRV association remains
a known limitation for simultaneous nearby launches.

Latest checks: 24 focused tests passed, lint/typecheck/build passed. iPhone
visual confirmation of group framing and impact timing remains required.

- Replaced sampled location shots with a persistent native-camera unit target.
  Every camera update follows the selected unit's previous/current tick position
  interpolation. Ordinary shots last 30 seconds; a missile keeps its shot for
  its lifetime. Camera restore and map-edge clamps remain in force.
- Visible missiles interrupt sightseeing. Candidate selection uses the existing
  nuke ID index, inspecting at most 256 entries each half second, not all units.
- Confirmed reached-target state produces an 8-second wider aftermath shot;
  interception does not masquerade as a detonation.
- MIRV separation widens for 2.5 seconds, then follows a nearby visible same-owner
  warhead. This association is proximity-based, not authoritative parent-child
  metadata; simultaneous nearby salvos may select a different matching warhead.
- Follow-up: 18 focused camera/UI/fog tests pass; TypeScript, lint and production
  build pass (existing asset/chunk warnings). Live missile/MIRV framing on iPhone
  still needs playtesting. No backend restart or production deployment.

- Implemented command-bar idle entry plus two-minute local input inactivity.
  Input activity, not simulation orders, resets the timer. Hidden tabs do not
  open a dashboard until visible; existing authoritative AFK semantics remain.
- Resume via triple short tap, Space, Escape or accessible resume button.
  Modal input isolation prevents map commands; original camera is restored.
- Native rendered board receives a single compositor perspective/orbit effect;
  native camera eases toward visible own structures/trains/warships, with a
  close zoom and a small moving offset. This is a planar 3D-looking board, not
  new volumetric geometry. Reduced motion disables movement and perspective.
- Removed the large dashboard surface in favor of transparent numeric readouts
  and bounded top-three history. No monitor shader or second world render.
- Added visible-water patrol center picking through the native camera transform;
  native warship patrol behavior determines the patrol area around that center.
- Follow-up verification: 29 focused tests passed, production build passed.
  Real-device cinematic framing/FPS, scrolling and multi-device/recovery gates
  remain open; v26.3 remains a development preview, not a production release.
